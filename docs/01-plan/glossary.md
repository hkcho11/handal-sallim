# 한달살림 핵심 용어집

> 상태: Draft
>
> 기준: `SERVICE_PLAN.md` 0.4
>
> 이 문서는 데이터 모델과 API에서 같은 개념을 같은 이름으로 사용하기 위한 초안이다. 미결정 항목은 `schema.md`의 결정 대기 목록을 따른다.

| 한글 용어 | 영문/코드 용어 | 정의 |
|---|---|---|
| 사용자 | User | 한달살림 계정을 가진 사람. 인증 수단과 계정 복구 정책은 별도 설계한다. |
| 관리 공간 | Space | 한 사용자가 혼자 관리하거나 두 사용자가 함께 관리하는 데이터 경계. 모든 고정비·청구·거래는 하나의 공간에 속한다. |
| 공간 멤버십 | Space Membership | 사용자와 관리 공간의 관계. 활성 멤버만 해당 공간의 공동 데이터에 접근할 수 있다. |
| 혼자 관리 | Solo Management | 활성 멤버가 한 명인 관리 방식. 공개 범위 선택을 화면에 노출하지 않는다. |
| 함께 관리 | Shared Management | 활성 멤버가 두 명인 관리 방식. 공동 데이터는 두 명에게, 개인 거래는 작성자에게만 보인다. |
| 초대 | Invitation | 두 번째 사용자가 관리 공간에 참여하도록 발급하는 만료형·일회용 자격 증명. 원문 대신 해시를 저장한다. |
| 결제수단 | Payment Method | 카드·계좌·현금의 표시 정보. 실제 카드번호와 계좌번호 전체는 저장하지 않는다. |
| 카테고리 | Category | 고정비와 거래를 분류하는 기준. 시스템 기본값과 공간별 사용자 정의값을 구분한다. |
| 반복 고정비 설정 | Recurring Expense | 비용명, 반복 간격, 기준 예정일, 최초 예상액, 담당자와 기본 결제수단을 가진 반복 규칙 원본. |
| 예정 청구 | Scheduled Charge | 반복 고정비 설정으로부터 특정 예정일에 한 번 발생한 월별·주기별 청구 스냅샷. |
| 예상 금액 | Expected Amount | 예정 청구가 완료되기 전에 보여주는 원 단위 정수 금액. 최초에는 사용자 입력값, 이후에는 직전 실제 금액을 사용한다. |
| 실제 거래 | Transaction | 실제 수입 또는 지출 기록. 사용자가 직접 만들거나 예정 청구 완료 시 자동 생성된다. |
| 자동 생성 거래 | Generated Transaction | 예정 청구 완료와 1:1로 연결되는 지출 거래. 직접 입력 거래와 출처를 구분한다. |
| 공동 거래 | Shared Transaction | 같은 공간의 활성 멤버 두 명이 조회할 수 있고 공동 합계에 포함되는 거래. |
| 개인 거래 | Private Transaction | 작성자만 조회할 수 있고 공동 목록·합계·통계에서 완전히 제외되는 거래. |
| 예정 | Pending | 예정일이 지나지 않았고 아직 완료되지 않은 예정 청구 상태. |
| 완료 | Completed | 실제 금액·결제일·결제수단이 확정되고 연결 거래가 존재하는 예정 청구 상태. |
| 지연 | Overdue | 예정 청구가 미완료이고 공간의 현지 날짜가 예정일을 지난 표시 상태. 별도 저장값이 아니라 계산값으로 다룬다. |
| 무효 처리 | Voided | 완료 취소 등으로 거래를 합계에서 제외하지만 기록 자체는 보존하는 상태의 제안 명칭. 보존 정책은 승인 전이다. |
| 멱등성 | Idempotency | 같은 요청이 재전송되어도 청구나 거래가 추가로 생성되지 않는 성질. |
| 서비스 내 리마인드 | In-app Reminder | Web Push 없이 홈에서 오늘 예정·임박·지연 항목을 우선 노출하는 기능. |

## 사용하지 않는 표현

- `가구주`, `배우자`: 관계와 성별을 전제하므로 사용하지 않는다.
- `고정비 내역`: 반복 설정인지 특정 회차인지 불분명하므로 `반복 고정비 설정` 또는 `예정 청구`로 구분한다.
- `지출 내역`: 직접 입력 거래와 자동 생성 거래를 구분해야 할 때는 출처를 함께 표시한다.
- `삭제`: 보관·무효 처리·영구 삭제 중 무엇인지 명확히 구분한다.
