# 고정비의 금액 변동 여부와 월별 결제 내역

2026-11-04 사용자 확정 정책이다. 기존 고정비 완료 팝업·예상 회차 정책보다 새 유형에 대해 우선한다.

## 등록과 전환

- 두 유형 모두 대분류·중분류·반복주기·반복 결제일·결제자·결제수단을 공통 설정으로 저장하고 상세에 표시한다. `VARIABLE`(금액 변동)은 등록 금액과 첫 결제일 대신 해당 월을 받는다. 해당 월과 설정한 결제수단은 첫 수동 입력의 기본값이다. 공통 반복 설정을 입력해도 변동 항목의 회차는 자동 생성하지 않는다.
- `FIXED`(금액 일정)는 금액·반복주기·반복 결제일·첫 결제일·기본 결제수단을 받는다. 첫 결제일은 지정한 날짜, 이후 회차는 반복 결제일을 사용하며 없는 날짜는 말일로 조정한다.
- 기존 항목은 `LEGACY`로 보존하고 임의로 자동 완료하지 않는다. 정보 수정에서 새 유형을 선택하면 전환일 이후부터 새 방식으로 기록한다. 기존 완료 내역과 연결된 거래는 보존한다. 기존 미완료 회차는 취소 상태로 남기며 새 방식의 미래 회차와 중복 기록하지 않는다.

## 수동 입력과 자동 기록

- 변동 항목에는 회차를 자동 생성하지 않는다. 상세 화면에서 해당 월·금액·실제 결제일·결제수단을 입력해 저장하는 즉시 완료 회차와 실제 지출 거래 한 건을 같은 트랜잭션으로 만든다. 결제 안내를 미리 받은 상황을 지원하므로 이 입력은 미래 결제일도 허용한다. 별도의 결제 완료 팝업·확인 단계는 없다.
- 같은 항목의 같은 해당 월에는 활성 수동 내역을 한 건만 둔다. 동일 요청 키의 재시도는 같은 결과를 반환하고 다른 내용·중복 월은 거부한다.
- 금액 일정 항목은 한국 시간으로 결제일이 된 회차까지만 완료 회차와 거래를 자동 생성한다. 매 1분 서버 작업으로 확인하고, 조회 시에도 빠진 회차를 복구한다. 서버 중단 후 복구와 동시 조회에서도 회차·거래를 중복 생성하지 않는다. 신규 등록 시 이미 지난 첫 결제일부터의 회차는 입력한 설정대로 생성한다.
- 사용 중인 기본 결제수단이 없으면 자동 기록을 중단하고 정보 수정으로 다시 지정하도록 안내한다. 보관된 결제수단의 과거 완료 기록은 유지한다.

## 표시·수정·집계

- 이름 아래의 장문 안내, 자동 생성 설명, 저장 후 성공 안내는 표시하지 않는다. 저장 결과는 갱신된 내역으로 확인하며 오류·로딩·빈 목록 안내는 유지한다.
- 회차는 해당 월 최신순으로 표시하며 상단 `해당 월 · 중분류`, 중간 결제 금액, 하단 `결제수단 · 실제 결제일`로 구성한다.
- 완료 내역은 상세 화면의 인라인 폼에서 해당 월·금액·실제 결제일·결제수단을 수정한다. 버전 충돌을 검출하고 완료 회차와 기존 거래를 함께 갱신한다. 반복 설정과 다른 회차의 금액은 바꾸지 않는다.
- `scheduled_charges.billing_month`가 있으면 집계 기준으로 사용하고 기존 기록은 예정 결제월을 유지한다. 실제 결제일과 거래의 `occurred_on`은 사실대로 보존한다. 예: 10월분을 11월 10일로 기록하면 10월 통계에만 반영한다.
- 다른 공간·비활성 사용자·보존된 읽기 전용 공간의 쓰기를 서버에서 거부한다. 공유 전환에서는 유형 설정만 이전하고 기존 완료 내역·거래는 복제하지 않는다.

## 배포 보류

현재 변경은 로컬 검증만 진행한다. 원격 푸시·PR 생성·main 병합·배포는 보류한다. 향후 배포에는 API와 V17·V18 migration을 프론트보다 먼저 반영해야 한다. V17은 기존 금액·거래를 수정하지 않고 nullable 금액과 새 유형·월 정보를 추가하지만 nullable 전환과 유일성 제약 교체 구문은 현재 새벽 배포 도구의 수동 검토 대상이다.
