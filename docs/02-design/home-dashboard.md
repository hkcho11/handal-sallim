# 고정비 홈 통계

기준: SERVICE_PLAN.md 1.3 및 2026-10-14 사용자 답변. 기존 홈의 지출 요약·일반 공동 거래 통계·등록 고정비 미리보기를 교체한다. 시각 기준은 기존 블루 토큰과 한글 폰트를 유지한다.

- 순서: 조회 월 → 대분류별 지출 통계 → 선택한 중분류별 월별 변화 → 결제수단별 지출. 별도의 실제 지출 요약 카드는 표시하지 않는다.
- 상단 조회 연월과 이전·다음 버튼 묶음은 화면 가운데에 배치한다. 연월 입력값은 가운데 정렬하고 달력 아이콘은 숨긴다. 기존 연월 입력과 이전·다음·이번 달 이동은 유지한다.
- 집계 월은 **예정 결제월**이다. 10월 청구를 11월에 결제해도 10월에 실제액을 반영한다.
- 대분류 차트는 실제/예상을 전환하며 처음에는 그 달의 실제 결제액을 표시한다. 펼친 분류는 배경색·제목색·화살표로 구분하고 높이·투명도를 부드럽게 전환한다. 닫힌 내역은 초점·스크린리더 탐색에서 제외하며 모션 줄이기 설정에서는 즉시 전환한다. 대분류 행을 펼치면 해당 고정비와 중분류, 금액·상태·결제일을 확인하고 지출 상세로 이동할 수 있다.
- 대분류의 백분율과 막대 길이는 해당 보기의 전체 금액 중 분류별 금액의 비중으로 통일한다. 실제 보기에는 `전체 실제 지출 대비 분류별 비중`, 예상 보기에는 `전체 예정액 대비 분류별 비중`을 안내한다. 최대 분류를 100%로 환산하지 않으며 전체 금액이 0원이면 백분율은 `—`, 막대 길이는 0으로 표시한다.
- 대분류 목록은 실제 보기에서는 실제 결제액 합계, 예상 보기에서는 예정 청구액 합계가 큰 순서로 정렬한다. 보기를 전환해도 펼친 분류는 유지한다.
- 미완료 건에는 예정 결제일과 서버 서울 기준일 대비 `D-N · N일 남음`, `D+N · N일 지연`, `D-Day · 오늘 결제`를 표시한다. 완료 건에는 실제 결제일을 표시한다.
- 분류 ID로 합산한다. 메모나 이름으로 그룹을 만들지 않으며 같은 중분류에 속한 여러 내역을 합산한다. 분류가 없는 기존 청구는 미지정으로 따로 표시한다.
- 중분류의 월별 비교는 선택 월까지 최근 6개월의 실제 결제액이다. 미결제 건은 0원이고 미결제 건수와 예정액을 함께 보여준다. 청구 기록 자체가 없는 달은 `기록 없음`이다. 반복 설정을 과거 달에 임의로 복제하지 않는다.
- 증감은 증가 시 빨간색 위 화살표(`▲ 10,000원 (22.2%)`), 감소 시 파란색 아래 화살표로 표시한다. 금액·비율의 부호는 화살표로 대신하고 스크린리더에는 증가·감소 방향을 제공한다. 변동이 없거나 전월 기록이 없으면 화살표 없이 중립색으로 표시한다. 전월 기록이 없으면 비교 기록 없음, 전월 기준액이 0원이면 증감액만 계산하고 증감률은 `—`이다.
- 월별 차트는 막대 위 금액을 `6.7만`처럼 축약하고 선택한 달의 정확한 금액·전월 대비 증감·미결제 건수와 예정액을 그래프 상단에 표시한다. 최초 선택은 조회 월이며 막대 클릭·터치·키보드로 변경한다. 기록 없는 달도 선택할 수 있다. 선택 월은 배경과 막대 색, 월 이름 굵기로 강조하며 스크린리더에 선택 상태와 정확한 금액·증감을 제공한다. 별도의 월별 금액·증감 펼침 표는 제공하지 않는다. 대분류·중분류 선택창에 접근성 이름을 제공한다.
- 결제수단은 미완료 청구의 **예정 결제수단/예정액**과 완료 청구의 **실제 결제수단/실제액**을 다른 열에 표시한다. 미지정도 별도 행이다. 결제수단 표시명이 같아도 ID가 다르면 합치지 않는다.
- 결제 일정·미결제 목록은 세 통계 아래의 접힌 영역에서 접근한다. 일정 미정 고정비는 별도 안내와 상세 링크로 확인하며 월 통계에 넣지 않는다.
- `/api/dashboard/fixed-costs?month=YYYY-MM`은 활성 공간 멤버에게만 제공한다. 예정 청구를 한 번만 반환하고 생성 거래·일반 거래·개인 거래·수입·저축을 합산하지 않는다. 취소 청구도 제외한다. 기존 `/api/dashboard`는 호환성을 위해 유지한다.
- 초기 월은 서버의 서울 날짜 기준 월이다. 이전/다음/월 입력과 이번 달 이동을 지원한다. 월을 바꾸면 이전 응답이 섞이지 않도록 새 조회 상태로 전환한다.
- 조회 월이 서버의 서울 날짜 기준 이번 달과 같으면 `이번 달` 버튼을 비활성화한다. 이전·다음 이동이나 연월 직접 입력으로 이번 달에 돌아와도 중복 조회를 발생시키지 않는다.
- `통계 새로고침`은 선택한 월을 유지하고 API를 다시 조회한다. 실패 시 재시도를 제공하며 이전 금액을 최신 통계로 표시하지 않는다.
- 테스트 데이터는 사용자가 로컬 DB에 준비한다. 홈은 `scheduled_charges`의 예정 결제월(`due_date`)과 실제 결제 정보로 집계한다. `recurring_expenses` 설정만 있거나 `transactions`에만 넣은 데이터는 월별 고정비 통계에 합산하지 않는다. 일정이 없는 활성 고정비는 별도 안내로 표시한다. 완료 데이터는 기존 완료 처리 API를 이용하면 청구와 실제 거래의 일관성을 유지할 수 있다.
