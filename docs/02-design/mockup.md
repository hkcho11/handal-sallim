# 한달살림 MVP 저충실도 와이어프레임

> 상태: Draft — 사용자 승인 전 구현 기준으로 사용하지 않음
>
> 목적: 시각 디자인 전에 정보 우선순위와 핵심 행동 위치를 합의한다.

## 1. 레이아웃 기준

| 구간 | 폭 | 기본 배치 |
|---|---:|---|
| 모바일 | 0~767px | 한 열, 하단 내비게이션, 전체 폭 입력 |
| 태블릿 | 768~1023px | 한 열 또는 2열 요약, 축약 내비게이션 |
| 데스크톱 | 1024px 이상 | 240px 좌측 내비게이션과 최대 1200px 콘텐츠 |

- 핵심 흐름은 360px 폭에서 가로 스크롤 없이 완료할 수 있어야 한다.
- 금액과 상태는 색상만으로 구분하지 않고 텍스트·아이콘을 함께 사용한다.
- 모바일 터치 대상은 최소 44×44 CSS px를 목표로 한다.
- 장식용 차트보다 날짜·금액·담당자·결제수단과 상태를 우선한다.

│ │ 나 · 결제수단 미지정      │ │
│ │              [완료하기]  │ │
│ └──────────────────────────┘ │
├──────────────────────────────┤
│ 이번 달                      │
│ 예상  1,120,000원            │
│ 확정    725,000원            │

│ 03  월세             지연    │

우선순위는 지연 → 오늘 → 임박 → 나머지 예정 → 완료다. 완료 항목은 기본적으로 접어서 정보 밀도를 낮춘다.

## 4. 통합 내역 등록 — 고정비 선택

```text
┌──────────────────────────────┐
│ ← 내역 추가                  │
├──────────────────────────────┤
│ 내역 유형 *                  │
│ [● 고정]       [ 일반 ]      │
│                              │
│ 비용명 *                     │
│ [예: 월세                 ]  │
│                              │
│ 최초 예상 금액 *             │
│ [650000                  ]원 │
│                              │
│ 반복 주기 *                  │
│ [매월] [격월] [분기] [매년] │
│                              │
│ 다음 결제 예정일 *           │
│ [2026-10-15              ]  │
│                              │
│ 선택 정보 · 나중에 입력 가능 │
│ 카테고리                     │
│ [미지정                  ▾]  │
│                              │
│ 담당자                       │
│ [미지정                  ▾]  │
│                              │
│ 결제수단                     │
│ [미지정                  ▾]  │
│ [+ 결제수단 추가]            │
│                              │
│ [취소]          [저장]       │
└──────────────────────────────┘
```

- 입력은 한 페이지로 유지하고 섹션 간 충분한 간격을 둔다.
- 금액은 입력 중 천 단위 구분 표시를 제공하되 서버에는 원 단위 정수를 보낸다.
- 날짜가 29~31일이면 없는 달에는 말일로 조정된다는 설명을 가까이에 표시한다.
- 카테고리, 담당자와 결제수단을 비워도 저장할 수 있고 상세 화면에서 보완할 수 있다.
- 유형을 전환할 때 사라지는 입력값이 있으면 전환 전에 확인한다.

│ 금액 *       [32,000      ]원│

## 10. 공통 화면 상태

### 빈 달

```text
이번 달 예정된 고정비가 없습니다.
[내역 추가]
```

### 조회 오류

```text
정보를 불러오지 못했습니다.
입력한 내용은 변경되지 않았습니다.
[다시 시도]
```

### 저장 충돌

```text
다른 변경이 먼저 저장되었습니다.
최신 내용을 확인한 뒤 다시 시도해 주세요.
[최신 내용 보기]
```

### 접근 불가

```text
이 항목을 볼 수 없습니다.
[홈으로]
```

다른 사용자 데이터의 존재 여부를 추론할 수 있는 상세 사유는 보여주지 않는다.

## 12. 검증 시나리오

- 360px 화면에서 공간 생성부터 결제수단 없는 첫 고정비 등록까지 가로 스크롤 없이 완료한다.
- 내역 유형을 고정/일반으로 바꿀 때 해당 입력 필드와 필수값 안내가 함께 바뀐다.
- 홈 진입 5초 안에 지연 항목, 금액, 담당자와 결제수단을 찾는다.
- 결제수단 미지정 청구에서 실제 결제수단을 선택하지 않으면 완료할 수 없다.
- 고정비 삭제 확인에서 취소될 현재·미래 회차와 보존되는 과거 기록을 구분한다.
- 함께 관리 거래에서 공개 범위를 선택하지 않으면 저장할 수 없다.
- 키보드만으로 내비게이션, 입력, 오류 확인과 제출을 완료한다.
- 200% 확대에서 주요 금액과 행동이 겹치거나 잘리지 않는다.
