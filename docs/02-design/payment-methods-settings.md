# 결제수단과 설정 탭

하단 메뉴는 홈·수입·지출·저축·설정 다섯 탭으로 구성한다. 개인 지출 화면은 제거했으며 지출 상세와 수정 화면은 지출 탭을 활성화한다.

## 결제수단

- `/payment-methods`: 사용 중·보관함 목록과 추가 링크. 종류와 명의자/담당자를 조합해 필터링하고 필터를 초기화할 수 있다. 명의자는 현재 공간 멤버와 미지정을 제공하며 조회 권한을 바꾸지 않는다. 목록에는 종류·명의자를 함께 표시한다. 목록과 고정비의 결제수단 선택지는 한국어 가나다순으로 정렬한다.
- `/payment-methods/new`: 이름·종류(신용카드, 체크카드, 간편결제, 계좌, 현금, 카드(미분류))를 필수로, 명의자/담당자와 표시 색상을 선택으로 입력한다. 새 등록은 신용카드를 기본으로 한다. 기존 `CARD`는 신용/체크 여부를 추정하지 않고 카드(미분류)로 보존하며 수정에서 종류를 지정할 수 있다. 번호 전체를 위한 입력 필드는 제공하지 않는다.
- `/payment-methods/[id]`: 표시 정보, 연결된 고정비, 수정과 보관 진입.
- `/payment-methods/[id]/edit`: 전체 표시 정보를 수정한다.

서버에서 활성 사용자와 공간 멤버십을 확인하고, 담당자는 같은 공간의 활성 멤버로 제한한다. 생성은 동일 요청 키의 재시도 시 중복을 방지하며 수정·보관은 버전으로 충돌을 검출한다.

신규 종류는 API와 V16 migration이 먼저 적용되어야 한다. V16은 기존 데이터를 변경하지 않고 종류 CHECK 제약을 교체하지만, 현재 새벽 배포 도구의 `DROP` 차단 대상이므로 수동 검토가 필요하다. 운영 API 준비 후 프론트를 반영하며, main 병합만으로 프론트가 자동 배포되는 점에 주의한다. 배포 보류 중에는 PR을 병합하지 않는다.

보관은 취소에 초기 초점을 둔 확인 팝업에서 실행한다. 과거 거래·완료 청구·당시 revision을 유지하고 현재 고정비와 미완료 예정 청구는 결제수단 미지정으로 바꾼다. 완료 청구가 참조한 revision은 새 revision으로 분리해 보존한다. 활성 선택 목록에서 보관된 결제수단을 제외한다. 보관함에서 조회는 가능하고 수정은 제공하지 않는다.

이번 화면은 연결 고정비의 설정 금액을 보여준다. 결제수단별 월간 예상·확정 지출 통계와 다음 결제 예정 요약은 후속 범위다.

## 설정

- `/settings`: 결제수단 관리, 지출 카테고리 관리, 사용 및 데이터 안내.
- `/settings/categories`: 같은 공간의 지출 카테고리를 조회·추가한다. 기존 고정비 API와 카테고리 저장소를 재사용하며 일반 지출에서도 선택할 수 있다. 이름은 공백 제거 후 1~80자이고 같은 활성 이름은 중복 생성하지 않는다. 이름 수정·보관은 기존 정책대로 후속 범위다.
- `/settings/guide`: 결제수단 보관, 한국 시간·원 단위 기준과 고정비 삭제 영향을 설명한다.

인증·초대·외부 알림은 해당 기능이 구현되는 시점에 설정에 추가한다.

## 검증 기록 (2026-10-14)

- 웹 전체 포맷·타입·린트·프로덕션 빌드 통과.
- 결제수단 응답 경계 Vitest 2건, 설정 Playwright 2건 통과. 등록·수정·보관, 취소/Escape/초점 복원, 카테고리 추가, 요청 실패 후 재시도와 360px·1280px·180px 폭에서 가로 넘침을 확인했다.
- API Spotless와 결제수단 통합 테스트 2건을 포함한 대상 빌드 통과. 중복 생성 방지, 버전 충돌, 인증·공간·담당자 검증, 완료 청구와 revision 보존·미완료 결제수단 해제·반복 보관을 확인했다.
- 웹 전체 테스트는 28건 중 기존 고정비 컴포넌트 4건 실패. 필수 카테고리 선택/fixture가 누락되어 저장을 수행하지 않는다.
- API 전체 테스트는 29건 중 기존 고정비 API 12건 실패. 요청에 필수 categoryId가 없어 400 응답이 발생한다. 기존 사용자 변경에 포함된 테스트와 요구사항 간 불일치이며 이번 작업에서 해당 테스트를 수정하지 않았다.
- 전체 E2E와 실제 iPhone Safari/Edge 확인은 실행하지 않았다. 브라우저 흐름은 API 응답을 모킹한 Chromium 테스트로 검증하고, 실제 PostgreSQL 데이터 일관성은 API Testcontainers 테스트로 확인했다.
- 변경은 기존 기능 브랜치의 작업 디렉터리에 남긴다. 이번 기능이 의존하는 고정비 카테고리·상세 화면 등 기존 사용자 변경이 아직 커밋되지 않았고 전체 검사도 실패하므로, 사용자 변경을 함께 커밋하거나 불완전한 PR을 제출하지 않았다.
