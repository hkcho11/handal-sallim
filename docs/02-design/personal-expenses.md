# 개인 지출 탭

2026-10-14 개인 지출 CRUD 구현 기준. 사용자는 삭제 확인 후 서버 기록의 영구 삭제와 지출명 필수 입력을 선택했다.

- 하단 메뉴는 홈, 고정비, 개인 지출 순서로 표시한다.
- 개인 지출 경로는 `/personal-expenses`이며 해당 화면에서 탭을 활성화한다.
- 서울 시간 기준 이번 달로 시작한다. 이전 달, 다음 달, 이번 달 이동을 제공한다.
- 월간 개인 지출 합계와 지출 내역 영역을 구성한다.
- 월간 합계는 본인의 활성 개인 지출만 집계한다. 조회 중이거나 실패한 경우 합계를 `—`로 표시하며, 성공한 빈 목록만 `0원`으로 표시한다.
- 빈 목록은 `등록한 개인 지출이 없어요`로 안내한다. 상세 조회에서 접근 가능한 내역이 없으면 오류 경고나 재시도 대신 `등록된 지출 내역이 없어요`와 목록·추가 진입을 표시한다. 실제 연결·서버·권한 오류는 별도로 안내한다.
- 지출 추가는 `/personal-expenses/new`, 상세와 수정은 `/personal-expenses/{id}`에서 제공한다. 저장 후 상세, 삭제 후 해당 거래가 속했던 월 목록으로 이동한다.
- 지출명(120자), 양수 원 단위 정수 금액, 날짜, 카테고리, 결제수단은 필수다. 메모(500자)는 선택이다. 미래 날짜도 허용하며 실제 거래일로 기록한다.
- 카테고리는 현재 공간의 활성 지출/공통 카테고리, 결제수단은 현재 공간의 활성 결제수단을 선택한다. 기존 내역을 수정할 때 동일한 보관된 참조는 유지할 수 있다.
- 개인 탭에서 생성하는 내역은 서버에서 `EXPENSE`, `PRIVATE`, `MANUAL`로 지정한다. 함께 관리에서는 매번 선택하지 않은 체크박스로 개인 등록을 명시 확인한다. 혼자 관리에서는 공개 범위 선택을 숨긴다.
- 서버는 활성 사용자·공간·멤버십과 작성자 일치를 조회·상세·수정·삭제에 모두 적용한다. 다른 사람의 내역은 404로 처리하고 개인 지출 존재 여부를 공개하지 않는다.
- 동일한 저장 키와 입력의 재시도는 같은 내역을 반환한다. 수정과 삭제는 조회한 버전이 일치할 때만 처리하며 충돌은 409로 안내한다.
- 삭제는 확인 팝업의 `삭제`를 눌렀을 때만 요청한다. 서버 행도 제거하며 복구할 수 없다. 취소/Escape는 요청하지 않고 진입 버튼으로 초점을 돌린다. 실패 시 내역을 유지하고 재시도한다.
- 합계는 JavaScript 안전 정수 범위를 넘어도 정확하도록 서버의 정수 합계를 문자열로 전달하고 클라이언트에서 BigInt로 검증·표시한다.

API는 `/api/personal-expenses`의 월별 GET, POST와 `/{id}`의 GET, PUT, DELETE, `/options`의 GET으로 구성한다. 생성은 `Idempotency-Key` 헤더를 요구하고 수정 본문과 삭제 쿼리에 `version`을 요구한다. 개인 응답은 `Cache-Control: no-store`를 사용한다.

`local` 프로필에만 테스트 사용자/공간, 기본 지출 카테고리(식비·교통·생활·쇼핑·의료·기타)와 현금을 준비한다. 이 프로필의 개인 지출 API는 로컬 테스트 사용자로 처리된다. 다른 프로필은 실제 인증 principal과 준비된 공간 선택지를 요구한다. 이 기능은 로그인 기능을 추가하지 않는다.

카테고리·결제수단 관리 UI, 개인 수입, 공동 거래와 통합 내역 추가 화면의 일반 거래 연결은 이번 범위에 포함하지 않는다. 기존 홈의 예시 합계에는 개인 지출을 합산하지 않는다.
