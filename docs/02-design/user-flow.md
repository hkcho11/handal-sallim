# 한달살림 MVP 사용자 흐름

> 상태: Draft — 사용자 승인 전 구현 기준으로 사용하지 않음
>
> 로그인·인증 완료 후의 제품 흐름만 다룬다.

## 1. 첫 공간 생성

```mermaid
flowchart TD
    A[서비스 진입] --> B{활성 공간 존재?}
    B -- 없음 --> C[공간 추가]
    C --> D{관리 방식 선택}
    D -- 혼자 --> E[SOLO 공간과 OWNER 멤버십 생성]
    D -- 함께 --> F[SHARED_PENDING 공간과 OWNER 멤버십 생성]
    F --> G[24시간 초대 발급]
    G --> H{상대 수락?}
    H -- 예 --> I[SHARED 전환]
    H -- 만료·취소 --> J[생성자 단독 사용 및 재발급 가능]
    E --> K[홈]
    I --> K
    J --> K
    B -- 있음 --> K
```

관리 방식에는 기본 선택값을 두지 않는다.

## 2. 첫 고정비 등록

2026-10-14 변경 흐름은 **지출 탭 → 우측 상단 추가 → 대분류 선택 → 소속 중분류 선택 → 선택 메모와 금액·일정·결제수단 입력 → 저장 → 상세**다. 메모 없이도 등록하며 중분류명을 표시명으로 사용한다. 필요한 분류는 설정의 분류 설정에서 추가한다. 대분류·중분류·금액은 필수이고 반복주기·반복 결제일·첫 결제일이 모두 정해졌을 때만 예정 청구를 생성한다. 아래 초기 Draft의 필수 지출명·단일 카테고리·통합 등록 진입보다 이 내용과 `SERVICE_PLAN.md` 1.4를 우선한다.

2026-10-13 확정 흐름: 고정비 탭(`/fixed-costs`)은 목록만 표시한다. 우측 상단 `+` → 추가(`/entries/new`) → 저장 후 상세(`/fixed-costs/[id]`)로 이동한다. 목록 항목도 같은 상세로 이동한다. 모든 정보는 상세의 `정보 수정`에서 편집하고 저장 후 상세로 돌아온다. 아래 초기 Draft 흐름보다 이 내용과 `SERVICE_PLAN.md`를 우선한다. 모든 화면의 구성은 [공통 UI/UX 가이드](ui-ux-guide.md)를 따른다.

```mermaid
flowchart TD
    A[홈 또는 주요 목록] --> B[내역 추가]
    B --> C{내역 유형}
    C -- 고정 --> D[비용명·금액·주기·첫 예정일]
    D --> E[카테고리 필수 선택 · 담당자·결제수단 선택 입력]
    E --> F{필수 입력 유효?}
    F -- 아니오 --> D
    F -- 예 --> G[반복 고정비와 첫 revision 생성]
    G --> H[서버가 첫 예정 청구 멱등 생성]
    H --> I[고정비 상세]
    C -- 일반 --> J[일반 거래 입력 필드로 전환]
```

카테고리는 등록·수정 시 필수다. 담당자와 결제수단은 선택 입력이며, 입력하지 않은 값은 `-`로 보여주고 고정비 상세에서 나중에 보완한다. 기존 카테고리 미지정 내역은 유지하되 수정 저장 시 선택해야 한다. 결제 완료 시에는 실제 결제수단을 필수로 선택한다.

## 3. 월간 홈과 결제 완료

2026-10-14 홈 구성은 대분류별 고정비 차트 → 중분류별 월간 변화 → 결제수단별 금액이다. 결제 일정 확인과 아래 완료 흐름은 유지한다. 월간 변화에서 미확정·기록 없음은 0원으로 처리하지 않으며 집계 월과 비교 금액의 정책은 구현 전에 확정한다.

```mermaid
flowchart TD
    A[월간 홈 요청] --> B[서버가 대상 월~다음 달 누락 청구 보충]
    B --> C[지연·오늘·임박 순서로 타임라인 표시]
    C --> D[예정 청구 선택]
    D --> E{상태}
    E -- 예정·지연 --> F[결제 완료]
    F --> G[실제 금액·날짜·결제수단 확인]
    G --> H[청구 COMPLETED + 자동 거래 ACTIVE]
    H --> I[갱신된 홈]
    E -- 완료 --> J[완료 내용 확인]
    J --> K[수정 또는 완료 취소]
    K --> I
```

저장 버튼을 연속으로 누르거나 네트워크가 재시도되어도 같은 자동 거래 한 건만 존재해야 한다.

## 4. 고정비 변경과 삭제

```mermaid
flowchart TD
    A[고정비 상세 또는 청구 상세] --> B{사용자 행동}
    B -- 이번 회차 변경 --> C[선택한 미완료 청구 스냅샷만 수정]
    B -- 다음 회차부터 변경 --> D[적용 시작 회차 확인]
    D --> E[새 revision 생성]
    E --> F[적용일 이후 미완료 청구 재계산]
    B -- 삭제 --> G[삭제 시작 회차와 영향 목록 확인]
    G --> H[반복 고정비 ENDED]
    H --> I[선택 회차와 이후 PENDING 청구 CANCELLED]
    I --> J[일반 화면에서 제거]
```

- 완료된 과거 청구와 거래는 어떤 경로에서도 변경하지 않는다.
- MVP에는 한 회차만 삭제하는 흐름이 없다.

## 5. 결제수단 보관

```mermaid
flowchart TD
    A[결제수단 상세] --> B[보관]
    B --> C[연결 고정비와 영향 안내]
    C --> D{확인?}
    D -- 취소 --> A
    D -- 보관 --> E[결제수단 ARCHIVED]
    E --> F[다음 미완료 회차부터 결제수단 미지정 revision]
    F --> G[과거 완료 기록은 기존 결제수단 유지]
```

대체 결제수단을 강제로 등록시키지 않는다. 결제 완료 시점에는 실제 결제수단을 필수로 선택한다.

## 6. 직접 거래 등록

```mermaid
flowchart TD
    A[홈 또는 주요 목록] --> B[내역 추가]
    B --> C[일반 선택]
    C --> D[수입 또는 지출]
    D --> E[금액·날짜·카테고리·결제수단]
    E --> F{함께 관리?}
    F -- 아니오 --> G[본인 데이터로 저장]
    F -- 예 --> H[공동 또는 개인 직접 선택]
    H --> I{선택했는가?}
    I -- 아니오 --> H
    I -- 예 --> G
    G --> J[해당 공개 범위 목록과 합계에만 반영]
```

상대 사용자의 개인 거래는 존재 여부, 건수와 금액까지 노출하지 않는다.

## 7. 혼자 관리에서 함께 관리로 전환

```mermaid
flowchart TD
    A[공간 관리] --> B[함께 관리로 전환]
    B --> C[공개될 고정비 미리보기]
    C --> D[기존 직접 거래 공개 범위 검토]
    D --> E{모든 거래 검토 완료?}
    E -- 아니오 --> D
    E -- 예 --> F[SHARED_PENDING 전환]
    F --> G[24시간 초대 발급]
    G --> H{상대 수락?}
    H -- 예 --> I[SHARED 및 공동 데이터 공개]
    H -- 취소·만료 --> J[전환 취소 또는 재발급]
```

초대 수락 전에는 기존 거래를 상대에게 공개하지 않는다.

## 8. 실패와 복구

| 실패            | 사용자 경험                                   | 데이터 규칙                      |
| --------------- | --------------------------------------------- | -------------------------------- |
| 목록 조회 실패  | 기존 화면을 지우지 않고 오류와 다시 시도 제공 | 조회가 쓰기를 중복 생성하지 않음 |
| 완료 응답 유실  | 다시 시도 가능                                | 같은 청구·거래 결과 반환         |
| 동시 수정 충돌  | 최신 값 안내 후 다시 확인                     | `version`으로 덮어쓰기 방지      |
| 초대 만료       | 만료 안내와 재발급 진입                       | 기존 token 재사용 차단           |
| 권한 상실       | 안전한 공통 오류와 홈 이탈                    | 데이터 존재 여부 추가 노출 금지  |
| 결제수단 미지정 | 경고 배지와 선택 행동                         | 완료 전 실제 결제수단 필수       |
