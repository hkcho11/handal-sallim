# 이메일·비밀번호 인증 구현 검증

기준일: 2026-10-26. 작업 브랜치: `feature/email-password-auth`.

## 변경 범위

- 가입·이메일 확인·확인 메일 재발송·로그인·세션 조회·로그아웃·비밀번호 분실·재설정 API와 한국어 화면.
- Spring Security PBKDF2(알고리즘 식별자 포함), CSRF 쿠키·헤더, 로그인·메일 발급 제한, 확인·재설정 토큰 단일 사용과 7일 보존 정리.
- Spring Session JDBC, 미사용 7일·절대 30일, 비밀번호 변경 후 기존 세션 거부.
- 미인증 업무 API 차단, 로컬 admin 자동 principal 제거, 신규 계정의 명시적인 첫 공간 생성.
- 지정 이메일 확인 후 기존 admin UUID에 자격 증명만 연결. 기존 금융 행과 소유권 참조는 변경하지 않음. 주소는 환경 메모리로만 지정하고 실제 주소를 문서에 기록하지 않음.
- Mailpit 개발 메일함, 인증 쿠키를 보존하는 웹 프록시, 모든 기능 클라이언트의 CSRF 헤더 전달.

## 검증

- API: `gradlew.bat spotlessApply test build` 성공. 최종 59개 테스트, 실패·오류 0.
- 인증 통합 테스트: 가입 확인 전 로그인 거부, 토큰 재사용·만료·재발급 무효화, 동시 가입 중복 방지, 동시 링크 소비 1회, CSRF 누락 거부, 시도 제한, 세션 지속·미사용 만료·절대 만료·사용자 비활성화, 재설정 뒤 모든 기존 세션·이전 비밀번호 거부, SMTP 장애 롤백·재시도, 인증 기록 정리.
- 기존 admin 연결: 다른 이메일의 확인으로 연결되지 않음, 지정 이메일도 확인 전에는 연결되지 않음, 확인 후 기존 수입 조회와 작성자·공간 ID 보존 검증.
- 웹: 단위 테스트 84개, 브라우저 테스트 37개 성공. 360px·1280px 가입 화면, 필드 안내, 확인 링크 fragment 제거, 로그인 오류·복귀 경로, 첫 공간 생성과 기존 금융 화면 회귀 검증.
- 웹 포맷·ESLint·타입 검사·프로덕션 빌드 성공.
- 실제 실행 API에서 HTTP 가입 → Mailpit 확인 메일 수신 → 링크 확인 → 로그인 → 공간 생성 → 로그아웃 → 기존 세션 401을 검증했다. 생성한 테스트 사용자·공간·메일은 정리했다.
- 인증 화면 스크린샷에서 줄바꿈·입력·버튼·가로 넘침 여부 확인.

## 남은 범위와 제출 상태

- 실제 iPhone Safari, 브라우저 종료 후 장기간 유지·실제 서버 프로세스 재시작 연속 동작, 실제 운영 SMTP 발송은 별도 환경에서 확인해야 함. JDBC 세션은 별도 요청·MockMvc 재구성 및 만료 DB 상태를 통해 확인했다.
- 초대 수락·이메일 변경·계정 탈퇴·소셜 로그인은 이번 범위가 아니다. 외부 공개 전 SMTP·발신 도메인과 프록시의 실제 클라이언트 IP 정책이 필요하다.
- 작업 시작 전부터 금융 기능·문서·개발 실행 도구의 대규모 미커밋 변경이 존재했다. 이 구현은 해당 변경을 보존한 현재 작업 트리에서 검증했다. 기존 변경을 임의로 커밋하거나 포함하지 않기 위해 커밋·PR 제출은 분리 방침 확인이 필요하다.
