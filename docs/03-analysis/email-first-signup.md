# 이메일 확인 뒤 비밀번호 설정

기준일: 2026-10-28. 사용자 요청: 가입 확인 전 공개 재가입으로 비밀번호가 교체되는 문제를 없애고, 아이폰 홈 화면 웹 앱에서 메일 링크를 열었을 때 복귀 방법을 확인한다.

후속 변경: 같은 날 사용자 요청으로 신규 메일을 링크 대신 인증번호 방식으로 전환했다. 최신 흐름과 검증은 [앱 내 인증번호 구현](email-code-authentication.md)을 따른다. 아래는 이전 링크 방식 변경 당시의 기록이다.

## 변경

- 가입 요청은 표시 이름·이메일만 받는다. 웹은 비밀번호를 입력·전송하지 않고, 서버도 가입 요청의 비밀번호 필드를 자격 증명으로 사용하지 않는다.
- 메일 링크를 열면 비밀번호·확인을 입력한다. `비밀번호 설정하고 가입 완료` 시 서버가 유효한 EMAIL_VERIFY 토큰과 비밀번호를 검증하고 해시·설정 시각·이메일 확인 시각·version 변경·토큰 소비를 같은 트랜잭션으로 완료한다.
- 비밀번호 누락·약한 비밀번호·유출 조회 장애는 가입을 완료하지 않고 링크를 소모하지 않는다. 만료·폐기·사용된 링크와 재설정 목적 토큰의 혼용은 기존과 같이 거부한다.
- 신규 미확인 계정은 비밀번호 해시와 설정 시각이 없다. V13은 두 필드의 NULL을 허용하되 인증 완료 계정은 반드시 두 필드를 갖도록 DB 제약을 추가한다. 기존 확인 계정의 ID·비밀번호·세션·금융 기록은 변경하지 않는다.
- 구버전 미확인 계정의 해시는 삭제하지 않지만 로그인 시 사용하지 않는다. 기존의 유효한 링크에서도 이메일 소유자가 비밀번호를 새로 설정해야 가입을 완료한다.
- 가입 확인 메일과 가입·재설정 완료 화면에 홈 화면 아이콘을 다시 열어 로그인하는 안내를 추가한다.

## 아이폰 홈 화면 복귀 검토

현재 프로젝트는 Next.js 웹이며 iOS 네이티브 앱·Associated Domains 구성이 없다. iOS 홈 화면 웹 앱과 Safari의 쿠키·저장소는 분리될 수 있으므로 Safari에서 로그인하면 기존 홈 화면 앱에도 로그인됐다고 가정할 수 없다. 메일에서 비밀번호 설정·재설정을 마친 뒤 홈 화면 아이콘을 다시 열어 같은 이메일·새 비밀번호로 접속하는 흐름으로 안내한다. 비밀번호 변경은 서버에 반영되므로 브라우저가 달라도 같은 자격 증명을 사용할 수 있다.

현재 웹 페이지에서 설치된 홈 화면 앱을 강제로 실행하는 버튼을 보장하지 않는다. 네이티브 앱의 Universal Links는 앱 entitlement와 도메인 연결이 필요한 별도 방식이다. 사용하지 않는 커스텀 URL 스킴이나 로그인 쿠키·비밀 토큰을 브라우저 간 전달하는 우회 기능을 추가하지 않았다.

앱 안에서 인증을 끝내는 것이 더 중요해지면 메일의 인증번호를 원래 앱에 입력하는 별도 흐름을 검토할 수 있다. 이번에는 링크 방식을 유지하며 OTP·폴링·실시간 알림·패스키를 추가하지 않았다.

`localhost`는 링크를 연 기기 자신이다. PC 로컬 서버를 가리키는 메일을 아이폰에서 열어 사용할 수 있다고 가정하지 않는다. 실제 사용 전 접속 가능한 고정 HTTPS 주소와 APP_PUBLIC_URL 설정이 필요하다. 아직 운영 도메인·배포가 없으므로 이번 변경에서 임의 외부 공개나 주소 전환은 하지 않았다.

근거: [Apple WWDC 홈 화면 웹 앱 설명](https://developer.apple.com/videos/play/wwdc2023/10120/), [WebKit 저장소 격리 설명](https://webkit.org/tracking-prevention/), [Apple Associated Domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains).

## 검증

실제 Gmail 발송·사용자 금융 기록 작성은 하지 않았다. 실제 iPhone Safari/홈 화면 설치 앱 검증은 이 Windows 환경에서 실행하지 못하며, 서로 다른 Chromium 컨텍스트에서 링크 완료 후 원래 컨텍스트로 로그인하는 서버 흐름과 구분한다.

- API `spotlessApply test build`: 전체 87건, 실패·오류·skip 0. 이메일 인증 전 비밀번호 없음, 공개 가입 요청의 비밀번호 무시, 이메일 소유자가 설정한 비밀번호만 유효, 누락·취약 비밀번호 시 토큰 유지, 구버전 미확인 계정 호환, 동시 링크 소비·재발급·만료·세션 무효화·기존 금융 기능 포함.
- 웹 format:check·lint·typecheck·build 통과. Vitest 전체 94건 통과.
- 화면 Playwright `e2e/auth.spec.ts`: 6건 통과. 360/1280px, 비밀번호 미입력 가입, 확인 불일치 안내, 비밀번호 설정 시점·토큰 주소 제거·완료 안내, 200% 글자 확대 시 가로 넘침 없음. 모바일 캡처 직접 확인.
- 첫 화면 검사에서는 Next.js route announcer와 제품 오류 안내가 모두 alert여서 테스트 선택자가 모호했다. main 내부로 선택자를 좁힌 뒤 6건을 재실행해 통과했다. 이를 제품 인증 실패로 판단하지 않았다.
- 실제 격리 통합 `scripts/test-auth-flow.ps1 -SkipBuild`: 5건 통과. SMTP 수신, 다른 컨텍스트에서 비밀번호 설정 후 원래 컨텍스트 로그인, 재가입 비밀번호 주입 거부, SMTP 중단·복구, 링크 재발급·재사용 거부, 비밀번호 재설정·기존 세션 거부, 회원코드 공유·보존·연결 해제 흐름 포함.
- `git -c core.safecrlf=false diff --check`: 통과.

## 남은 범위

이번 변경은 보안 점검의 인증 전 재가입 문제를 해결하는 범위다. 프록시 실제 IP 식별·요청 제한, Next.js 보안 버전 업그레이드, 웹 보안 헤더, 해시 비용 강화와 비밀번호 최소 길이 정책은 별도 후속 작업이다. 이번 변경만으로 공개 배포 보안 검증이 끝났다고 판단하지 않는다.
