# 홈·수입·고정비·설정 개선

기준일: 2026-10-29. 기존 작업 트리를 유지하며 사용자 체크리스트와 후속 답변을 반영했다.

## 결정과 구현

- 홈 미결제 건수는 표시하지 않는다. 차트 접근성 안내에도 미결제 건수 문구를 제거했다. 홈 드롭다운 간격은 사용자가 기존 수정으로 확인해 추가 변경하지 않았다.
- 수입은 사용자 ID별 합계·건수·이름을 표시하는 펼침 목록으로 구성했다. 하나의 소유자를 열면 이전 목록은 닫힌다. 전체 월 합계·수정·삭제·공유 범위는 그대로다. 원 단위 정수 합산에 BigInt를 사용한다.
- 고정비 키워드를 입력하면 카테고리를 전체로 바꾸고 필터 스크롤을 처음으로 돌린다. 이름·분류·메모·결제수단 전체 검색을 지원한다. 카테고리를 다시 선택하면 검색어를 지우며 검색·상세 왕복 상태 복원은 유지한다.
- 결제수단 목록에 설정 복귀 링크를 추가하고 선택한 사용 중/보관함은 파란색, 비선택 상태는 회색으로 구분했다. aria-pressed도 유지했다.
- 상위 분류 이름 버튼에서 수정 팝업을 연다. 저장 실패 시 입력을 유지하고, 같은 이름과 오래된 수정 요청을 거부한다. ID를 유지하므로 관련 내역의 이름도 함께 바뀐다.
- 별도 드래그 아이콘 대신 테두리가 있는 분류명 버튼으로 상위 분류 순서와 세부 분류 순서·상위를 바꾼다. 상위 분류는 클릭하면 수정하고 드래그 후 클릭은 억제한다. 버튼 외의 영역은 스크롤할 수 있으며 드래그 중 화면 가장자리에서는 자동 스크롤한다. 드롭 영역 밖으로 나가거나 Escape·pointercancel이면 취소한다. 화살표 키 순서 변경과 별도 옮기기 버튼도 제공한다.
- 다른 상위로 이동할 때 과거 통계 영향 안내를 확인한다. 사용자 요청에 따라 현재 가계부의 과거·현재 반복 설정, 예정/완료 청구, 실제 거래 분류를 함께 이동한다. 금액·결제일·기록 ID·권한·소유권은 유지한다. 대상에 동명의 세부 분류가 있으면 병합하지 않고 오류를 안내한다.
- V15로 순서 필드·기본 분류 초기화 표식·분류 FK의 ON UPDATE CASCADE를 추가했다. 기본 분류 재생성을 방지하고, 보존 공간의 금융 행은 수정하지 않는다. 공간 잠금과 이전 이름·형제 순서·상위 ID 검사로 중복·동시 변경을 방어한다.
- 실제 연동 검사에서 이전 결제 완료 구현이 거래에 subcategory_id를 복사하지 않던 문제를 발견했다. 신규 결제는 청구의 세부 분류도 함께 저장하며, 분류 이동 시에는 같은 활성 공간의 명시적인 scheduled_charge_id 연결을 기준으로 기존 거래의 누락·불일치를 보완한 뒤 이동한다. 수동 거래나 보존 공간을 임의로 추정·수정하지 않는다. 원래 거래의 ID·금액·날짜가 유지되는 회귀 검사도 강화했다.

## 검증

실제 사용자 거래를 테스트용으로 생성·수정하거나 실제 이메일을 발송하지 않았다. 실제 데이터에 대한 분류 재배치도 실행하지 않았다. 마이그레이션의 순서 메타데이터 적용과 테스트에서의 분류 이동은 구분한다.

- 웹 포맷·린트·타입 검사·프로덕션 빌드 통과, Vitest 96개 통과.
- 최종 API spotlessCheck·test·build 통과. JUnit 100개, 실패·오류·건너뜀 0개. V14 보존 공간을 V15로 올리는 별도 마이그레이션 검사도 포함한다.
- 관련 기존 브라우저 흐름 9개와 추가 개선 흐름 5개 통과. 360px·1280px, 200% 확대, 키보드 순서 변경, 터치·마우스 이동, 영역 밖 드롭 취소, 새로고침 후 유지와 결제수단 버튼을 확인했다.
- 초기 검색 테스트의 상속된 이름 때문에 전체 검색 결과가 달라져 픽스처를 바로잡았다. 이동 대상 선택창은 실제 통합 검사에서 접근성 이름 문제를 발견해 명시적 aria-label을 추가하고 회귀 검사했다.
- 실제 API·격리 PostgreSQL·Mailpit·웹 통합 검사 5개 통과(최종 49.3초). 공유 상대방의 분류 이동 후 양쪽 홈 통계와 완료 청구가 같은 분류로 변경되는지 검증했다. 이 검사로 기존 결제 거래의 세부 분류 누락을 발견해 수정했으며, 서버 회귀 검사는 누락된 기존 거래까지 재현한다.
- git diff --check 통과. 기존 다른 작업이 함께 있는 브랜치여서 커밋·PR에는 제출하지 않았다.

## 제한과 남은 작업

- 실제 iPhone Safari·홈 화면 앱의 손가락 드래그는 별도 확인이 필요하다. Chromium 터치 입력 재현과 실제 기기 확인을 동일하게 취급하지 않는다.
- 보존된 가계부의 분류 편집·자동 병합·분류 삭제는 이번 범위가 아니다.
- 기존 인증·배포 보안 점검 후속 항목은 별도로 유지한다.

## 후속 UI 개선: 드롭다운과 분류명 드래그

- 홈·수입 펼침 목록에 공통 SVG 화살표와 펼침 상태 색상을 적용했다. 수입은 홈과 같은 60px 최소 높이·간격·글자 크기로 맞췄다. 모든 단일 선택창은 홈 기준의 12px 테두리 곡률, 배경·높이·초점 표시를 공유한다. 기존 네이티브 선택 동작과 지원 브라우저의 옵션 팝업 스타일은 유지한다.
- 분류명 전체를 테두리 버튼으로 바꿨다. 별도 점 모양 손잡이는 없앴고, ‘눌러 수정 · 끌어 이동’ 안내, 잡는 커서, 드래그 원본 강조와 목적지 점선으로 동작을 알린다. 상위 분류의 짧은 클릭·Enter는 이름 수정, 드래그는 이동으로 구분한다. 다른 상위로 옮길 때의 확인 절차는 그대로다.
- 웹 린트·포맷 검사·타입 검사·프로덕션 빌드, Vitest 96개 통과. 홈·수입·분류·결제수단 관련 브라우저 검사 26개 통과. 360px·1280px, 200% 확대, 마우스·Chromium 터치, 키보드, 실제 텍스트 영역 이동과 드래그 후 수정창 오작동 방지, 공통 선택창 스타일을 확인했다. 두 폭의 화면 캡처도 확인했다.
- 초기 단위 검사에서 Vite의 경로 별칭 미지원으로 공통 컴포넌트 import가 실패해 기존 상대 경로 방식으로 수정했다. 자동 스크롤 도입 후 브라우저 검사는 가려진 옛 좌표 대신 현재 표시 위치를 확인하도록 보완했다.
- 서버·DB 변경은 없어 이 후속 UI 작업에서 서버 검사는 반복 실행하지 않았다. 실제 iPhone Safari 터치 확인은 여전히 남아 있다.

## 분류 편집 의도 보완

- 목록의 ‘끌어 이동·옮기기’ 문구와 별도 이동 버튼을 제거했다. 들여쓰기·연결선과 테두리로 상위·세부 구조를 표시하고, 눌림·잡는 커서·드래그 중 그림자·목적지 점선으로 조작 상태를 표시한다.
- 상위 분류는 이름을, 세부 분류는 이름과 소속 상위 분류를 직접 수정한다. 드래그로도 순서·상위를 변경할 수 있다. 소속 변경 시 과거 내역·통계 영향은 수정창과 드롭 확인창에서 안내한다.
- 세부 분류 편집 API는 공간 잠금 아래 이름·소속을 원자적으로 갱신한다. 원래 이름·소속의 충돌 검사와 대상의 동명 검사, 현재 공간 권한을 적용한다. 대상에서 사용 가능한 이름이면 기존 상위에 같은 이름이 있어도 이름·소속 동시 변경을 허용한다. FK 연쇄 변경과 기존 결제 거래 연결 보완은 유지한다. 별도 DB 마이그레이션은 없다.
- 검증: API spotlessCheck·test·build 통과(101개, 실패·오류 0개), 웹 빌드와 Vitest 96개 통과. 관련 브라우저 8개와 격리 서버 통합 5개 통과. 이름·소속 동시 변경, 중복·동시 수정 거부, 과거 실제 거래 분류 갱신, 입력 보존 후 재시도, 터치·마우스 드래그와 키보드를 확인했다. 360px·1280px 캡처와 200% 확대도 확인했다.
- 처음 브라우저 검사에서 닫힌 이동창과 편집창의 동일 레이블이 겹쳐 닫힌 이동창의 내용은 렌더링하지 않도록 수정했다. 통합 검사 중 프로덕션 빌드를 동시에 교체해 페이지 로드가 실패한 실행은 무효로 보고, 최종 빌드를 고정한 재실행에서 5개 모두 통과했다(49.8초). 오류 안내 검사는 Next 라우트 안내와 혼동하지 않도록 활성 수정창 안으로 범위를 좁혔다.
- 로컬 API를 새 JAR로 재시작했다. 실제 사용자 분류나 거래를 테스트용으로 바꾸지는 않았다. 실제 iPhone Safari 손가락 조작은 별도 확인이 필요하다.

## 계층 연결선과 화면 우선순위 보완

- 이전 수정에서는 참고 사이트를 다시 확인하지 않았으며, 목록 전체의 border-left가 마지막 세부 분류 아래까지 남는 시각 오류를 놓쳤다.
- WWIT 설정 패턴 페이지에서 monimo_setting_01 화면을 직접 다시 확인했다. 구획·여백·목록 정보 위계를 참고했으며, 해당 사례가 분류 트리나 드래그 구현 예시라고 주장하지 않는다. UI Bowl 모으미 상세는 현재 로그인 안내가 가려져 확인하지 못했다. 기존 참고 문서와 새 확인 사실을 구분한다.
- 연결선을 각 행에 나눠 그리고 마지막 행은 중심에서 끝내도록 변경했다. 세부 분류가 없는 목록에는 선이 없고, 한 항목·여러 항목·줄바꿈·확대에도 마지막 가로 연결선 아래로 세로선이 내려가지 않는다.
- 기존 분류 목록을 추가 폼보다 먼저 배치해 화면 진입 시 현재 계층부터 보여준다. 편집·드래그·추가 동작과 저장 정책은 유지한다.
- 빌드·타입 검사·포맷 검사 및 관련 브라우저 10개 통과. 360px·1280px와 200% 확대에서 선의 실제 계산 위치, 빈 분류, 직접 편집·드래그·키보드·추가를 확인했다. 테스트 자료로 만든 두 폭의 화면 캡처를 직접 확인했다. 서버 변경은 없다.

## 추가 입력 간소화

- 목록 아래 상위·세부 추가 폼 두 개를 제거하고 제목 옆 `+ 추가` 한 버튼으로 통합했다. native dialog에서 종류를 선택하며 상위 분류는 이름, 세부 분류는 소속과 이름만 입력한다. 기존 편집·이동 UI와 API는 유지한다.
- 자동 초점, X·취소·Escape 닫기와 버튼 초점 복귀, 필드별 검증, 실패 후 입력 보존, 저장 중 닫기·중복 제출 차단, 성공 시 추가 항목으로 스크롤·초점 이동을 적용했다. 상위 분류가 없을 때는 먼저 상위를 만들도록 세부 추가를 비활성화한다.
- 360px·1280px·200% 확대의 브라우저 검사를 추가했고, 기존 설정 흐름도 팝업 진입 방식으로 수정했다. 서버와 DB 변경은 없어 서버 검사를 반복하지 않는다. 실제 iPhone 가상 키보드가 열린 화면은 별도 확인이 필요하다.
- 검증 결과: 웹 린트·포맷·타입 검사·빌드, Vitest 96개와 관련 브라우저 13개 통과. 초기 기존 설정 테스트에 팝업 열기 단계를 잘못된 결제수단 위치에 삽입해 실패했고, 분류 설정 진입 뒤로 수정한 재실행에서 해당 2개 모두 통과했다. 팝업의 360px·1280px 화면 캡처도 직접 확인했다.

## 사용 중인 분류 목록 압축과 검색

- 큰 그룹별 테두리·들여쓰기·연결선을 제거하고 하나의 목록 안에서 상위 제목·세부 개수와 얇은 구분선으로 묶었다. 세부 항목은 이름 길이에 맞춰 가로 배치·줄바꿈하며 최소 44px 터치 높이를 유지한다. 긴 이름을 생략하거나 줄 수로 잘라 숨기지 않는다. 펼침·접기는 사용하지 않는다.
- 전체 상위·세부 이름을 공백·대소문자를 정규화해 검색한다. 상위 이름 일치 시 소속 항목 전체를, 세부 이름 일치 시 해당 항목을 소속 경로와 함께 보여준다. 결과 건수·결과 없음·검색 초기화를 제공한다.
- 검색 중 직접 수정은 가능하고 부분 목록에서 순서를 바꾸는 조작은 차단한다. 이름 수정으로 결과에서 사라지면 검색창으로 초점을 돌리고, 새 분류 추가 시 검색을 해제해 저장된 항목으로 이동한다. 전체 목록의 클릭 수정·상위 이동 확인·드래그와 키보드 정렬은 유지하며 가로 항목에는 좌우 화살표 정렬도 지원한다.
- 검증: 웹 포맷·린트·빌드(타입 검사 포함), Vitest 96개, 관련 브라우저 13개 통과. 360px·1280px·200% 확대, 실제 가로 배치·줄바꿈·터치 크기, 소속 경로 검색·검색 결과 수정·초점 복귀·검색 중 추가와 기존 드래그·팝업 흐름을 확인했다. 양쪽 폭의 화면 캡처도 직접 확인했다. 서버·DB 변경은 없어 서버 검사는 반복하지 않았다. 실제 iPhone Safari 터치는 별도 확인이 필요하다.

## 드래그 중 실제 배치 미리보기

- 목적지의 실선·점선 강조를 제거했다. 드래그 중 원본 데이터와 별도의 임시 배치로 상위 그룹·세부 박스를 즉시 재배치하고, 포인터에는 그림자가 있는 분류명, 들어갈 자리에는 반투명 항목을 표시한다. 목적지 박스의 좌우 위치로 세부 항목 앞·뒤를 구분하며, 상위 그룹은 위·아래 위치로 정렬한다.
- 세부 항목이 다른 그룹으로 재배치되어 DOM이 바뀌어도 드래그가 끊기지 않도록 이동 시작 시 안정적인 목록 요소로 pointer capture를 넘긴다. 화면 가장자리 자동 스크롤은 유지한다. 놓기 전에는 API를 호출하지 않는다.
- Escape·pointercancel·영역 밖 드롭은 원래 배치로 복원한다. 순서 저장 실패 시에도 원래 목록과 오류를 보여준다. 다른 상위로 이동할 때는 임시 배치를 유지한 상태로 기존 통계 영향 확인창을 열고, 취소하면 복원하며 확정해야 저장한다. 확인창의 소속 선택을 바꾸면 미리보기도 맞춰 갱신한다. 기존 순서 저장 성공 문구는 표시하지 않는다.
- 검증: 최종 웹 린트·포맷·빌드(타입 검사 포함), 관련 브라우저 16개 통과. Vitest 96개도 통과했다. 마우스·Chromium 터치의 놓기 전 배치, 저장 전 요청 0회, 성공 후 새로고침 유지, Escape·목록 밖·touchCancel·소속 확인 취소, 저장 실패 복원을 확인했다. 360px·1280px 드래그 화면 캡처를 직접 확인했다.
- 첫 브라우저 실행에서 모바일 크기의 검색 수정 후 초점 복귀 검사가 실패했다. 편집창의 실제 close 이벤트 이후에 복귀하도록 보완한 최종 재실행에서 검색·수정·드래그 흐름이 모두 통과했다. 실제 iPhone Safari 터치는 별도 확인이 필요하다. 서버와 DB는 변경하지 않았다.
