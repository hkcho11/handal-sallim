# 월별 수입 검증 기록

2026-10-15, `feature/monthly-income` 브랜치의 현재 작업 디렉터리 기준이다.

- 웹: Prettier, ESLint, TypeScript, 전체 Vitest 39건, 프로덕션 빌드 통과.
- API: Spotless, 전체 JUnit·PostgreSQL Testcontainers 40건, 빌드 통과. 수입 API 4건과 로컬 프로필 실제 HTTP 1건을 포함한다.
- 수입 Playwright 3건 통과: 등록·새로고침 후 조회·월 이동 수정·삭제·빈 합계, 조회 실패 후 재시도, 저장 실패 시 입력 및 재시도 키 유지.
- 수입 화면의 360px·1280px·180px 폭, 360px에서 글꼴 200% 확대 시 가로 넘침 없음. 삭제 확인창의 초기 취소 포커스, Escape와 트리거 포커스 복귀 확인. 모바일 스크린샷 육안 확인.
- 전체 Playwright 최초 실행은 14건 중 10건 통과, 4건 실패했다. 수입 2건은 Next.js의 route announcer도 `alert`로 검색되는 테스트 선택자 문제로 `main` 안의 알림으로 한정한 뒤 재실행해 통과했다.
- 남은 고정비 E2E 2건(360px·1280px)은 `apps/web/e2e/fixed-expense.spec.ts:117`에서 `/통신비/` 링크를 기대하지만 화면이 `인터넷`을 표시해 실패했다. 수입 구현에서 변경하지 않은 고정비 화면·fixture의 불일치이며 이번 범위에서 수정하지 않았다.
- 실제 iPhone Safari와 Edge 실행은 수행하지 않았다. 브라우저 E2E는 Chromium과 모의 API 응답을 사용하고, 실제 DB·서버 API 연결은 Testcontainers와 HTTP 통합 테스트로 검증했다.

기존 고정비·설정·로컬 실행 관련 미커밋 변경을 유지했다. 수입 경로를 기존 로컬 admin 필터에 추가했으며 기존 파일 전체를 새 수입 변경으로 커밋하지 않았다. 해당 선행 변경과 분리한 PR은 아직 제출하지 않았다.

## 실제 개발 서버 확인 (2026-10-15 13:23 KST)

- 사용자 수동 테스트 실패를 확인한 결과, 웹 3000 포트의 `/backend/incomes`와 API 8081 포트의 `/api/incomes` 모두 404였다. API 프로세스는 수입 기능 구현 전인 12:41에 시작된 버전이었다. 기존 모의 브라우저 테스트와 별도 통합 테스트만으로 실제 실행 서버가 갱신되었다고 볼 수 없었다.
- 해당 API 프로세스를 최신 코드와 `local` 프로필로 재시작했다. Flyway가 기존 V5 데이터베이스에 V6 수입 테이블 migration을 적용했고, 웹 프록시를 통한 월별 조회가 200으로 바뀌었다.
- 실제 `http://127.0.0.1:3000/income` 화면에서 동작확인용 1원 수입을 등록하고, 페이지를 새로고침한 뒤 내역과 합계가 유지되는 것을 확인했다. 모의 응답 없이 로컬 API와 PostgreSQL에 연결한 결과다. 확인 후 해당 테스트 내역만 API로 삭제하여 목록·합계에서 제외했다.

## 월 선택 UI 간소화 (2026-10-15)

- 조회와 등록·수정의 월 달력을 이전·다음 달 버튼과 월 표시로 교체했다. 다른 월에서는 `이번 달`로 돌아오고, 새 등록은 조회 중인 월을 기본값으로 사용한다.
- Prettier, ESLint, TypeScript, 전체 Vitest 39건, 프로덕션 빌드와 수입 Playwright 4건 통과. 연도 경계 이동, 키보드 조작, 조회 월과 등록 월의 독립 변경, 월 변경 후 CRUD·재시도 흐름을 확인했다.
- 실행 중인 웹 3000 포트에서도 이전 달 조회와 등록 폼의 기본 월 연결을 확인했다. API 프록시 조회는 200이었다. 백엔드 코드는 변경하지 않아 API 테스트는 이번 UI 수정에서 다시 실행하지 않았다. 실제 iPhone Safari는 미검증이다.

## 등록·수정 페이지 분리 (2026-10-15)

- 목록 안의 등록·수정 폼을 제거하고 `/income/new`, `/income/{id}/edit` 전용 페이지로 이동한다. 고정비처럼 목록 링크에서 진입하고 뒤로가기·취소를 제공한다. 진입 월은 URL로 전달하고 저장하면 저장한 월의 목록으로 돌아온다.
- 수정 페이지는 단건 API 응답을 검증해 불러오며 새로고침·직접 진입을 지원한다. 조회 실패 시 빈 폼으로 저장하지 않고 재시도를 제공한다. 등록 재시도 키와 수정 버전 검사는 유지한다.
- Prettier, ESLint, TypeScript, 전체 Vitest 40건, 빌드, 수입 Playwright 5건 통과. 등록 화면에서 조회 월·합계가 없는 것, 수정 화면 새로고침, 취소 후 진입 월 유지, 저장 후 변경 월 조회, 수정 조회 실패 후 재시도를 확인했다.
- 전용 등록 폼은 360px·1280px와 200% 글꼴 확대에서 가로 넘침이 없었고 모바일 스크린샷을 확인했다. 실행 중인 웹 3000 포트에서도 목록 링크가 전용 등록 페이지로 이동하는 것을 확인했다. API 구현은 변경하지 않았으며 API 테스트는 재실행하지 않았다. 실제 iPhone Safari는 미검증이다.
