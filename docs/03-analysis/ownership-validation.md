# 수입·저축 소유자 검증 기록

2026-10-15, `feature/income-savings-owners`의 현재 작업 디렉터리 기준이다.

- 사용자 결정: 새 등록의 기본 소유자는 작성자 본인이고 같은 공간의 다른 활성 멤버를 선택할 수 있다. 공유 범위는 유지한다. 기존 데이터는 작성자를 소유자로 연결한다.
- `owner_user_id`를 작성자와 별도로 저장하고 공간 멤버 복합 FK로 보호한다. 서버는 등록 시 소유자 생략을 본인으로, 수정 시 생략을 기존 소유자 유지로 처리한다. 새 소유자 지정은 활성 사용자·멤버십을 검사한다. 이전 멤버의 기존 소유 기록은 유지한다.
- 수입 목록·등록·수정, 저축 목록·상세·등록·수정에서 소유자를 확인할 수 있다. 등록은 본인이 자동 선택되며 서버가 제공한 공간 멤버 목록만 선택지로 사용한다.
- API: Spotless·전체 PostgreSQL Testcontainers/JUnit 48건·빌드 통과. 소유자 생략 기본값, 작성자와 소유자 분리, 다른 멤버 지정·변경, 수정 시 기존 소유자 유지, 잘못된 공간·탈퇴 멤버 차단, 소유자가 달라도 공유 조회 유지, 소유자 변경 요청 키 충돌을 포함한다.
- 최초 API 검사에서 잘못된 소유자 입력을 리포지토리가 예외로 던져 500으로 처리하던 문제를 발견했다. 리포지토리는 판정값을 반환하고 애플리케이션 서비스에서 입력 오류로 거부하도록 수정하여 400 응답을 확인했다.
- 웹: Prettier·ESLint·TypeScript·전체 Vitest 68건·프로덕션 빌드 통과. 소유자 응답의 본인·중복·이름 검증과 수입·저축 응답의 소유자 경계를 검사한다. 최초 Vitest의 새 별칭 해석 실패는 기능 API의 공용 모듈 경로를 상대 경로로 맞춘 뒤 해결했다.
- 수입·저축·원화 입력 Playwright 9건 통과. 본인 기본 선택, 다른 멤버 선택·저장 후 목록·상세 이름 표시, 수정 화면 새로고침, 기존 CRUD·월 이동·금액 정밀도·입력 커서 동작을 확인했다. 초기 E2E는 select 라벨의 엄격 일치와 폼 화면에서 목록 표시를 검사하던 위치 문제를 수정한 뒤 통과했다.
- 실행 중인 로컬 API를 최신 코드로 재시작하고 V8 migration 적용을 확인했다. 실제 웹 3000 포트에서 수입·저축 소유자 목록 API가 200이며 본인이 멤버 목록에 포함됨을 확인했다. 실제 등록 화면에서 소유자를 바꾸지 않고 저장한 테스트 수입·저축이 본인 이름으로 조회되었고 저축 새로고침 후에도 유지되었다. 검증에 만든 두 내역만 삭제해 합계에서 제외했다.
- 기존 사용자 데이터의 금액·공유 범위는 바꾸지 않았다. 모바일 목록 스크린샷에서 소유자 이름을 확인했고 관련 E2E의 모바일·데스크톱 폭·200% 글꼴 검사를 통과했다. 실제 iPhone Safari·Edge는 미검증이다.
- 기존 미커밋 변경을 보존했으며 관련 선행 변경과 분리한 PR은 아직 제출하지 않았다.
