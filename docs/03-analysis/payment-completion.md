# 결제 완료와 금액 미정 반복 회차

기준일: 2026-10-27. 현재 기능의 실제 금액 확정과 다음 회차 생성을 구현했다. 완료 내용 수정·완료 취소는 이번 범위에 포함하지 않는다.

## 사용자와 확정한 동작

- 반복 주기와 결제일에 따라 첫 결제일부터 빠진 예정 회차를 생성한다. 자동으로 결제 완료하지 않는다.
- 실제 결제일은 예정일을 기본으로 수정할 수 있으며 한국 날짜 기준 미래 실제 결제일은 차단한다.
- 다음 달 예상액은 필요하지 않다는 후속 결정에 따라 이전 실제액을 이월하지 않는다. 등록 금액만 고정비 정보에 표시하고 이후 회차는 금액 없는 예정·지연 상태로 표시한다. 실제 금액은 완료 화면의 빈칸에 입력한다.
- 홈 합계·분류 차트·월간 비교·결제수단 집계는 완료 금액만 사용한다. 미결제만 있는 달을 0원으로 비교하지 않고 기록 없음과 미결제 건수를 함께 표시한다. 기존의 예정 결제월 기준 집계는 유지한다.

## 구현

- `ScheduledChargeService`와 `ScheduledChargeStore`가 활성 사용자·공간 확인/잠금, 반복 회차 생성, 버전 검사, 실제 결제 확정과 거래 생성을 담당한다. 월 조회와 고정비 목록/등록·일정 설정·완료에서 중복 없이 회차를 생성한다.
- 첫 회차는 첫 결제일을 유지하고 다음 회차는 기준 월에 반복 개월 수를 더한 뒤 반복 결제일을 적용한다. 없는 날짜는 말일로 조정한다. 최신 revision의 적용 시작일과 활성 상태를 검사하고 취소된 회차는 ON CONFLICT DO NOTHING으로 되살리지 않는다.
- 실제 금액은 양의 원 단위 정수·안전 정수 범위를 검증한다. 소수 금액은 정수로 잘라 저장하지 않고 거부한다. 결제수단은 같은 공간의 활성 수단이며 완료와 1:1 실제 거래 생성을 같은 트랜잭션으로 처리한다.
- 같은 내용 재시도와 두 멤버의 동시 수락은 거래를 한 건만 생성한다. 다른 내용의 재확정과 오래된 버전은 409, 다른 공간의 단건 접근은 404, 미래 결제일/사용할 수 없는 결제수단은 400이다. 중간 실패 시 완료와 거래가 모두 롤백된다.
- V12 migration은 `scheduled_charges.expected_amount`의 NOT NULL만 제거한다. 기존 금액과 완료 내역은 유지하고 새 후속 회차는 NULL로 저장한다. JPA·API 검증·공유 보존 기록은 NULL을 0원으로 바꾸지 않는다. 공유 시 고정비 등록 금액을 이어받고 직전 실제액으로 바꾸지 않는다.
- 고정비 상세에서 회차 목록과 완료 확인 dialog를 제공한다. 홈의 특정 청구 링크에 청구 ID를 전달해 해당 행을 구분한다. 실제 금액은 빈칸, 날짜는 예정일, 결제수단은 사용 가능한 예정 수단을 기본 선택한다. 오류 시 입력을 유지하고 실제 처리 전에는 명시적 확인을 받는다.

## 검증

- API `spotlessApply test build` 성공: 전체 85개, 실패·오류 0. 월말·윤년·분기·매년, 과거 미생성 회차, 재조회 중복 방지, 실제 거래 1건, 상대 멤버 처리·제3자 차단, 미래 날짜·소수 금액·오래된 버전·보관 수단 거부, 동시 완료, 거래 생성 실패 시 롤백을 검증했다.
- 웹 단위·컴포넌트 전체 92개 통과. 실제 금액만 정렬/집계하고 미결제만 있는 달의 증감을 생성하지 않는 기준으로 기존 검사를 갱신했다. 이후 홈 API의 실제 합계 검증 변경에 대해 관련 파서 5개를 추가 재실행해 통과했다.
- ESLint·타입 검사·Prettier 확인과 프로덕션 빌드 성공. 일반 Chromium 회귀 37개 통과.
- 임시 PostgreSQL·Mailpit·별도 API·프로덕션 웹의 실제 통합 5개 통과. 가입·인증·로그인·공유 흐름 안에서 빈 실제 금액/예정일 기본값, 완료 확정, 거래 1건, 다음 회차 NULL, 양쪽 홈의 같은 실제 금액을 확인했다. 기존 연결 해제·기록 보존 검사도 함께 실행했다.
- 완료 dialog의 360px·1280px 스크린샷을 생성하고 360px 이미지를 직접 확인했다. 이미지는 `.local/payment-complete-360.png`와 `.local/payment-complete-1280.png`에 둔다.
- 360px에서 루트 글꼴 200% 확대 시 가로 넘침이 없고 완료 버튼에 스크롤로 접근할 수 있는지 실제 통합 검사에 추가했다. 해당 5개 흐름과 마지막 소스의 웹 단위 92개를 재실행해 모두 통과했다.
- 초기 검사에서 기존 테스트의 ‘첫 회차만 존재’와 ‘예상액으로 집계’ 전제를 새 정책에 맞게 바꿨다. 보관 결제수단의 오류가 500으로 번역되는 문제는 명시적 400 응답으로 수정하고 재검증했다.

## 회차 목록·완료 팝업 후속 조정

- 회차 목록의 API와 화면을 예정일 내림차순으로 정렬했다. 화면은 응답 순서와 관계없이 정렬하며 고정비 목록의 가장 이른 미결제 회차 선택 규칙은 바꾸지 않았다.
- 목록 카드 폭을 정보 카드와 같은 640px 이내로 맞추고, 날짜·상태·결제수단 및 행 사이의 간격과 글자 크기를 조정했다. 팝업의 중복 문단 여백을 줄였다.
- 하단 돌아가기 대신 제목 오른쪽 44px X 닫기를 제공한다. 키보드 Escape 동작과 처리 중 닫기 방지는 유지한다.
- 실제 금액에만 `WonInput.digitsOnly`를 적용했다. 문자·붙여넣기의 숫자 외 문자를 걸러내고 천 단위 쉼표 및 숫자 위치 기준 커서 복원을 유지한다. 다른 금액 입력의 기본 동작은 유지한다.
- 정적 검사·빌드와 관련 API 5개, 브라우저 3개(360px·1280px 목록/팝업, 기존 금액 커서 회귀)가 통과했다. 브라우저는 X 닫기 시 저장 없음, 숫자 전용·쉼표·커서·붙여넣기, 실제 정수 전송, 200% 확대를 확인한다. `.local/charge-list-360.png`와 `.local/charge-dialog-360.png`를 직접 검토했다.
- 실제 통합 검사 재실행에서 해제 요청 전송·거절 응답 전에 다른 계정을 새로고침하던 검사 경합이 드러났다. 처리 후 화면 상태를 기다리도록 검사를 동기화한 뒤 5개 통합 흐름이 모두 통과했다. 관련 없는 해제 제품 정책은 변경하지 않았다.

## 로컬 적용과 남은 범위

- 저장된 Gmail 암호화 설정을 자동 복원해 로컬 API를 재입력 없이 재시작했다. V12 migration 적용과 API 준비·감시 상태 및 Gmail 설정 유지를 확인했다. 새로고침 후 새 기능을 사용할 수 있다.

- 실제 iPhone Safari와 운영 호스팅/원격 CI는 실행하지 않았다. 완료 수정·취소, 회차별/다음 회차부터 반복 설정 변경 선택은 후속 기능이다.
- 실제 사용자에게 테스트 지출이나 메일을 만들지 않았다. 기존 광범위한 미커밋 작업은 보존했으며 해당 작업을 임의로 커밋·PR에 묶지 않았다.
