# 예적금 저축 검증 기록

2026-10-15, `feature/savings-crud`의 현재 작업 디렉터리 기준이다.

- 사용자 선택: 공간 멤버에게 공유하며 현재 금액은 등록·수정 시 직접 입력한다. 예금의 예치 금액·적금의 월 납입액과 현재 금액은 독립적이며 자동 납입·이자 계산은 하지 않는다. 기존 저축은 이미 모은 금액, 새 저축은 0원으로 시작할 수 있다.
- 목록·상세·별도 등록·수정 페이지와 삭제 확인창을 구현했다. 삭제 내역은 목록·합계에서 제외하고 DB에 보존한다. 중복 등록 키·수정 버전 검사와 공간 권한 경계를 적용했다.
- API: Spotless, 전체 JUnit·PostgreSQL Testcontainers 46건, 빌드 통과. 저축 API 4건과 로컬 프로필 실제 HTTP 1건을 포함한다. 기존 잔액, 월 납입액과 현재 금액의 독립성, 예금 제외 월 합계, 중복·충돌·삭제 보존, 타 공간·탈퇴 멤버 차단, 0원 시작, 소수·음수·안전 정수 초과 거부, 큰 합계의 정밀도를 확인했다.
- 웹: Prettier, ESLint, TypeScript, 전체 Vitest 64건(저축 API 경계 9건 포함), 프로덕션 빌드 통과.
- 저축 Playwright 3건 통과. 기존 적금과 예금 등록·새로고침·상세·수정·삭제·합계, 조회 실패 재시도·잘못된 수정 ID 차단, 0원 신규 저축·저장 실패 후 입력과 재시도 키 유지를 확인했다.
- E2E 최초 실행은 수정 링크 클릭 직후 페이지 이동 전에 새로고침하여 상세 화면에 머무르는 테스트 대기 문제로 1건 실패했다. 수정 URL 도달을 확인한 뒤 새로고침하도록 고쳐 재실행했으며 3건 모두 통과했다.
- 등록 폼의 360px·1280px 폭과 200% 글꼴 확대에서 가로 넘침이 없었고 모바일 폼·목록 스크린샷을 육안 확인했다. 삭제 확인창의 취소 초기 포커스·Escape 복귀를 확인했다. 실제 iPhone Safari·Edge 실행은 미검증이다.
- 실행 중인 이전 JAR API는 저축 경로 확인에 시간 초과했다. 실행 경로를 확인해 해당 프로세스를 종료하고 최신 코드의 `local` API를 재시작했다. V7 migration 적용 후 실제 웹 3000 포트의 저축 API 프록시가 200으로 응답했다.
- 모의 응답 없이 실제 화면에서 테스트 저축(월 납입액 1,000원, 기존 금액 5,000원)을 등록하고 새로고침 후 유지, 현재 금액 6,000원 수정까지 확인했다. 해당 테스트 내역만 API로 삭제해 목록·합계에서 제외했다. 기존 사용자 데이터는 수정하거나 삭제하지 않았다.
- 기존 수입·고정비·홈·설정의 미커밋 작업을 보존했다. 저축은 기존 공용 원화 입력과 로컬 admin 설정에 의존하며 관련 선행 작업과 분리한 PR은 아직 제출하지 않았다.
