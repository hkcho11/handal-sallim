# 함께 쓰기 전체 기능 점검

점검일: 2026-10-26. 기준은 현재 화면과 API에 구현된 기능이며, 전체 기획 항목의 완료 여부는 구분한다.

2026-10-27 후속: 아래 미구현 목록 중 연결 해제는 양쪽 동의 방식으로 구현했다. [연결 해제 구현과 검증](sharing-disconnect.md)을 따른다. 나머지 목록은 당시 점검 결과다.

2026-10-27 추가 후속: 결제 완료와 반복 회차 생성도 구현했다. 사용자 후속 결정에 따라 예상액 이월 대신 금액 없는 예정 회차와 완료 실제액 기준 통계를 사용한다. [결제 완료 구현과 검증](payment-completion.md)을 따른다. 완료 수정·취소는 아직 후속 범위다.

## 현재 기능의 공유 지원

| 기능 | 점검 결과 |
|---|---|
| 회원코드 연결 | 요청·상대 확인·수락 후 같은 SHARED 공간 사용. 상태는 수동 새로고침 |
| 홈 통계 | 두 계정의 같은 조회 월에 같은 고정비·금액·결제수단 데이터 반영. 결제자 표시는 조회 사용자에 따라 나/상대로 달라짐 |
| 수입 | 상대가 만든 내역 조회·수정·삭제 가능. 소유자는 별도 표시하며 수정자가 바뀌어도 기존 소유자 유지. 양쪽 소유자 선택 목록에 두 멤버 표시 |
| 저축 | 상대가 만든 내역 조회·수정·삭제 가능. 현재 모은 금액과 납입액·합계 공유. 두 멤버의 소유자 선택 가능 |
| 지출/고정비 | 등록·조회·정보/일정 수정·삭제, 결제자 나/상대 선택 지원. 상대가 변경한 금액을 다른 계정과 홈에서도 확인 |
| 결제수단 | 같은 목록 사용. 다른 멤버가 수정·보관 가능. 보관 후 연결된 미완료 고정비의 결제수단 해제도 양쪽에 반영 |
| 분류 설정 | 한 계정이 추가한 상위 분류와 다른 계정이 추가한 세부 분류를 양쪽 고정비 옵션·분류 화면에서 조회 |
| 연결 전 기록 | 원래 사용자만 별도 보존 화면에서 읽기. 공유 목록·합계에 포함되지 않으며 다른 멤버에게 공개되지 않음 |
| 제거된 개인 지출 | 외부 API 접근도 거부하므로 새 개인 지출을 만드는 별도 경로 없음 |

소유자·결제자 지정은 기록의 담당 표시이며 새 공유 기록을 해당 사용자에게만 숨기는 권한 설정이 아니다. 조회 월·필터·펼침·스크롤 등 화면 선택은 브라우저별로 유지한다. 같은 데이터 조회 조건에서 공유 데이터를 비교했다.

## 실제 실행한 검증

- `SharingApiTest`에 실제 회원코드 연결 후 전 기능을 교차 사용하는 테스트 2개를 추가했다. 기존에 멤버십을 테스트 데이터로 직접 만드는 검사와 별개로, 요청·수락으로 만들어진 공간에서 동작을 검증한다.
- 수입·저축: A 등록 → B 수정 → A 재조회 → B 삭제 → A의 합계 0. 소유자 보존과 제3자 단건 접근 차단 확인.
- 설정·지출: A 상위 분류 → B 세부 분류, A 카드 등록 → B 명의자/이름 수정, A 고정비 등록 → B 금액·결제자 수정 → 양쪽 홈에 같은 금액/카드 반영, B 카드 보관 → A 고정비 연결 해제, B 고정비 삭제 → A 목록·홈에서 제외 확인.
- 제3자는 공유 카드 수정·고정비 삭제·수입/저축 단건 조회를 할 수 없고, 자신의 홈에 공유 데이터가 나타나지 않는지 확인했다.
- 실제 Chromium 통합 검사를 확장했다. 두 계정이 회원코드로 연결된 상태에서 수입·저축·고정비·결제수단·분류 화면에 같은 새 항목이 나타나는지, 수입/저축 등록 화면의 소유자 옵션에 두 멤버가 있는지, 양쪽 홈이 오류 없이 표시되는지 확인했다.
- API 전체 `spotlessCheck test build`: 76개 테스트, 실패·오류 0.
- 실제 PostgreSQL·SMTP를 연결한 브라우저 통합 검사: 5개 통과. 외부 응답을 가로채지 않으며 임시 DB·Mailpit과 별도 API·웹 서버를 사용했다.
- 웹 포맷·ESLint·타입 검사 성공. 테스트만 추가했고 제품 코드는 변경하지 않아 기존 웹 단위/화면 모의 검사는 이번 점검에서 반복하지 않았다.
- 기존 Gmail 개발 서버는 재시작하거나 설정을 바꾸지 않았고 준비·감시 상태가 유지됨을 확인했다. 실제 회원에게 시험 요청·공유 연결·메일을 만들지 않았다.

## 아직 구현되지 않은 기획 항목

현재 기능의 공유 지원이 전체 서비스 기획의 구현 완료를 뜻하지는 않는다.

- 결제 완료 확정과 실제 지출 거래 생성, 완료 취소의 사용자 화면/API가 없다. 현재의 `completeSchedule`은 비어 있는 반복 일정을 보완하는 기능으로 결제 완료 처리가 아니다.
- 반복 고정비의 다음 회차를 계속 자동 생성하는 실행 경로가 없다. 최초 등록·일정 수정 시 회차를 만들고 표시하는 기능과 구분한다.
- 공유 연결 해제·상대 교체는 후속 정책/구현 범위다.
- 데이터는 공유하지만 상대 화면을 실시간으로 갱신하는 기능은 없다. 화면 진입·재조회·새로고침 후 최신 내용을 확인한다.
- 연결 전 사용하던 결제수단·분류 전체를 자동 공개하지 않는다. 새 공유 공간의 기본 설정과 이어받은 반복 고정비에서 참조하는 설정을 사용한다.

실제 iPhone Safari·외부 호스팅·운영 도메인과 원격 GitHub Actions 실행은 이번 점검 범위가 아니다. 기존의 대규모 미커밋 변경은 보존했으며 임의로 커밋·PR에 포함하지 않았다.
