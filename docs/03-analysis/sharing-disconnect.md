# 양쪽 동의로 함께 쓰기 연결 해제

기준일: 2026-10-27. 사용자는 기존 공유 기록의 양쪽 읽기 전용 보존·각자 새 개인 공간·자동 이월 없음·재연결 시 새 공유 공간이라는 기본안에 동의하고, 해제에 양쪽 동의를 요구했다.

## 동작

- 설정 → 함께 쓰기 → 연결 해제 요청 → 영향 확인 후 요청 전송.
- 상대가 `요청 상태 새로고침` → 해제 요청 확인 → `동의하고 연결 해제`를 눌러야 종료한다. 요청·확인만으로 종료하지 않는다. 요청자는 취소, 상대는 거절할 수 있고 요청은 24시간 후 만료한다. 알림·자동 갱신은 추가하지 않았다.
- 수락은 공유 공간 보관, 양쪽 활성 멤버십 종료, 당시 두 멤버의 읽기 전용 접근 등록, 각자의 새 개인 공간 생성, 요청 처리를 한 트랜잭션으로 수행한다.
- 공유 수입·저축·고정비/예정 기록은 보존 화면에서 확인하고 현재 합계에서는 제외한다. 기존 개인 기록의 본인 전용 권한은 유지한다. 기존 금융 데이터는 삭제하지 않는다.
- 새 개인 공간은 기본 분류·현금으로 시작하며 잔액·반복 설정·사용자 결제수단/분류를 복사하지 않는다. 다시 연결해도 새로운 공유 공간을 만들고 이전 공유 기록은 새 상대에게 공개하지 않는다.

## 권한과 경합

- 기존 V10을 수정하지 않고 V11 migration을 추가했다. 연결 종료 시각과 활성 연결 부분 UNIQUE, 해제 요청, 두 멤버별 공유 보존 접근을 저장한다.
- 요청/결정 시 사용자 행을 UUID 순서로 잠그고 연결과 요청을 재조회한다. 자기 요청 수락/거절·상대 요청 취소는 403, 제3자 처리는 404, 만료·취소·거절 요청 재사용과 종료된 공간에 새 요청은 409로 거부한다.
- 서로 요청을 보내도 자동 수락하지 않는다. 같은 요청의 수락 재시도는 새 개인 공간을 중복 생성하지 않으며 과거 요청/공간은 새 연결을 종료할 수 없다.
- 수락 시 공유 공간을 잠가 진행 중 쓰기와 직렬화한다. 보존 공간의 금융 쓰기는 기존 DB 트리거와 현재 공간 기반 API 권한으로 차단한다.

## 검증

- API 전체 `spotlessCheck test build`: 80개 테스트, 실패·오류 0. 해제와 보존·격리·재연결, 권한·만료·거절·취소, 동시 중복 수락, 개인 공간 생성 실패 시 전체 롤백을 추가했다.
- 웹 단위/컴포넌트 89개 통과. 포맷·ESLint·타입 검사와 프로덕션 빌드 성공.
- 임시 PostgreSQL·Mailpit·API·프로덕션 웹으로 실제 브라우저 통합 5개 통과. 기존 회원가입·인증·로그인 흐름에 실제 두 계정의 해제 취소·거절·수락, 빈 개인 공간, 양쪽 보존 기록·개인 기록 격리를 추가했다.
- 해제 요청 확인 화면을 360px·1280px 및 200% 확대에서 가로 넘침 없이 확인했고 키보드로 요청 확인을 열었다. 스크린샷은 `.local/disconnect-360.png`, `.local/disconnect-1280.png`이며 Git에 포함하지 않는다.
- 일반 브라우저 회귀 검사 첫 실행은 36개 통과·기존 계정 페이지 이동 1개 시간 초과였다. 같은 검사의 단독 재실행과 2 worker의 전체 재실행 37개가 모두 통과했다. 이 실패를 근거로 관련 없는 제품 코드를 변경하지 않았다. 마지막 파서 수정 후 공유 API 단위 검사 4개도 재실행해 통과했다.

## 실행 환경

- 통합 검사는 실제 개발 DB와 Gmail을 사용하지 않았다. 실제 회원에게 해제 요청이나 메일을 보내지 않았다.
- 기존 로컬 API는 메모리에만 있는 Gmail 설정으로 동작하므로 새 API 적용에 숨김 입력 터미널을 열었다. 입력과 SMTP 확인이 끝나야 로컬 서버가 재시작되어 V11과 새 API가 적용된다. 비밀번호를 코드·파일·로그에서 읽거나 저장하지 않았다.
- 숨김 입력 완료 후 SMTP 연결 확인과 로컬 API 재시작이 성공했다. 실제 개발 DB에 V11 migration 1개 적용, API 준비·감시 상태 정상 및 Gmail 설정 유지를 확인했다. 테스트 메일은 보내지 않았다.
- 실제 iPhone Safari·운영 호스팅·원격 CI는 실행하지 않았다. 기존의 광범위한 미커밋 작업은 보존했으며 이번 변경과 섞어 임의로 커밋·PR로 제출하지 않았다.
