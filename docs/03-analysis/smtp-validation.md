# 실제 SMTP 연결 검증

검증일: 2026-10-26. 브랜치: `feature/email-password-auth`.

2026-10-27 후속: 사용자 요청에 따라 메모리 전용 보관에서 Windows DPAPI 암호화 저장·자동 복원으로 변경했다. 재입력 관련 과거 기록은 당시 결과이며 현재 동작은 [SMTP 로컬 암호화 저장](smtp-credential-storage.md)을 따른다.

## 결정과 적용

- 사용자는 보유 도메인이 없고 배포 전이므로 Gmail SMTP로 먼저 연결하고 배포 시 전용 발송 서비스로 전환하기로 선택했다.
- Google 앱 비밀번호는 별도 PowerShell 숨김 입력으로 받고 프로세스 환경에만 전달했다. 코드·문서·상태 파일·명령 인수에는 실제 발신 주소나 키를 남기지 않았다.
- `smtp.gmail.com:587`, SMTP 인증, STARTTLS 필수, 인증서 호스트 검증을 적용했다.
- 독립 SMTP 검사로 TLS 로그인과 본인 주소에 대한 테스트 메일 서버 수락을 확인했다. 사용자가 실제 테스트 메일 수신도 확인했다.
- 현재 API 시작 로그의 활성 프로필은 `local,mail-smtp`이며, 실행 상태는 Gmail·감시 실행·준비 완료다. 가입 확인·비밀번호 재설정 메일도 같은 Spring JavaMailSender 설정을 사용한다.

## 검사

- `gradlew.bat spotlessCheck test build` 성공: 66개 테스트, 실패·오류 0.
- 외부 메일 설정 테스트: 운영 HTTPS·Secure 쿠키 강제, 로컬과 운영 프로필 혼합 거부, 필수 자격 증명 누락 거부, TLS·인증서 검증 비활성화 거부, 디버그 로그 활성화 거부, Gmail 발신 주소 불일치 거부.
- SMTP 검사 도구 테스트: 수신자를 지정하지 않으면 메일을 보내지 않음, 연결 성공 후 명시된 수신자에게만 발송, 연결 실패 시 원문 예외·주소·키를 출력하지 않음.
- PowerShell 스크립트 구문 검사 성공.
- 실제 Gmail 설정 후 비밀값이 없는 별도 셸에서 API 재시작을 시도해, 기존 서버를 중단하기 전에 재설정을 요구하는지 확인했다. API PID는 유지됐다.
- `git diff --check` 성공. 웹 코드는 이번 SMTP 변경에서 수정하지 않아 이전 브라우저·웹 테스트를 반복하지 않았다.

## 운영 전 남은 범위

- 현재 인증 링크는 localhost 개발 서버를 가리킨다. 다른 기기·외부 사용자용 링크로 쓸 수 없다.
- 새 셸에서 API를 다시 시작하거나 PC를 재부팅하면 `scripts/configure-smtp.ps1 -Provider Gmail`로 키를 다시 입력한다. 감시 프로세스가 서버를 자동 복구하는 동안에는 메모리에 상속된 설정을 사용한다.
- 운영 배포 시 보유 도메인·HTTPS 사이트·DNS 인증과 전용 SMTP 발송 계정을 준비하고 호스팅 비밀 환경 변수로 저장한다. 이번 작업은 서비스를 공개 배포하거나 유료 도메인·요금제를 구매하지 않았다.
- 공급자 실제 일일 한도 소진·반송·스팸 분류·외부 호스팅 SMTP 포트 허용은 검증하지 않았다. 테스트 메일의 수신 확인이 이후 모든 메일의 도착을 보장하지 않는다.
- 이전 작업부터의 미커밋 변경은 그대로 보존했다. 기존 변경의 커밋 포함 범위는 아직 확인되지 않아 임의로 커밋·PR에 포함하지 않았다.
